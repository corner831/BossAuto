## 1. v2 针对你提的三个问题做了什么

### ① "只能精确匹配" → 改成三级判断
1. **本地规则**（免费、即时）：排除关键词 / 公司黑名单 / 薪资区间 / 关键词。
2. **JD 参与匹配**：用同源 `fetch` 拉取职位详情页正文，**职位描述里的技能词现在也算命中**。
   v1 的 bug 是 `selectors.js` 定义了 `jobDesc` 却从未读过 —— 所以"技能只写在 JD 里"的岗位永远匹配不上。
3. **大模型打分**：把「你的求职画像 + 职位信息 + JD」交给模型打 0-100 分，低于阈值跳过。

### ② "不能翻页刷新新岗位" → 两个都修了
- **翻页**：点击"下一页"后对比「卡片列表签名 / 地址」是否真的变化，变了才继续；
  多套候选选择器 + 按文字兜底。
- **滚动加载**（2026-11 实测 BOSS 已改成滚动加载、页面上没有"下一页"元素）：
  找不到"下一页"按钮或按钮禁用时，会**自动滚动到底部触发加载**，连续滚动 3 次确认列表变长；
  只有滚动后仍然没有新职位、或页面出现"没有更多"字样，才判定结束。
- **导航续跑**：若翻页触发整页刷新导致脚本被销毁，进度先落盘，新页面注入后**自动接着跑**（v1 会静默丢任务）。
- **新岗位刷新**：一轮翻完后可等待 N 分钟重新搜索，靠历史记录只投新岗位。

### ③ "要更智能" → 用大模型逐条打分
见下面第 4 节的配置方法。

## 2. 安装 / 更新

**首次安装**
1. Edge 地址栏输入 `edge://extensions`
2. 打开左下角「开发人员模式」
3. 「加载解压缩的扩展」→ 选中本仓库根目录（含 `manifest.json` 的文件夹本身）
4. 打开 BOSS 页面按 `F5` 刷新一次

**从 v1 更新（如果你之前已经装过 v1）**
1. `edge://extensions` → 找到本插件 → 点**「重新加载」**
2. 回到 BOSS 页面按 `F5` 刷新（**必须做**，否则页面里还是旧脚本）
3. 打开插件弹窗，会看到新增的「AI 智能匹配」「新岗位刷新」两个折叠面板

**Chrome**：`chrome://extensions` → 右上角「开发者模式」→「加载已解压的扩展程序」→ 同一目录。

## 3. 第一次使用

1. 登录 <https://www.zhipin.com>，进入职位搜索页（地址必须是 `https://www.zhipin.com/web/geek/job...`）

## 4. AI 智能匹配怎么配（核心新增）

点开「AI 智能匹配」面板：

| 字段 | 填什么 |
|---|---|
| 启用 AI 打分 | 勾上才生效。不勾 = 只跑本地规则（快、免费） |
| 接口地址 | 兼容 OpenAI `chat/completions` 的地址。**可只填域名**，如 `https://api.deepseek.com`（默认） |
| 模型名 | 默认 `deepseek-flash`。**注意：`deepseek-chat` 已从官方模型列表下线**，填它可能报模型不存在。可选 `deepseek-flash` / `deepseek-v4-pro` |
| 阈值 | 分数 ≥ 此值才投，默认 70。想更激进调到 60，保守调到 80 |
| API Key | 你的 key，只存在本机浏览器存储 |
| 我的求职画像 | 随便写：YAML / JSON / 大白话都行，**原样发给模型**（插件不做任何格式推断，也不加注解） |
| 自定义判断标准 | **可选**。写了就整段替换默认口径；画像字段怎么解读、什么算硬性排除，全由你决定。留空则用默认（只有两句话：你是求职顾问 + 依据画像判断） |

### 4.1 怎么拿到 API Key

1. 打开 <https://platform.deepseek.com/api_keys>（DeepSeek 开放平台），用手机号/邮箱登录。
2. 点「创建 API key」，起个名字（如 `boss-auto-apply`），复制生成的 `sk-` 开头的字符串。
3. **这个 key 只显示一次**。页面之后只保留掩码（形如 `sk-abcd****wxyz`），看不到完整值；
   如果当时没复制，只能删掉重建一个。
4. 确认账户里有余额，否则调用会返回余额不足。

其他兼容 OpenAI 的服务（月之暗面、硅基流动、各类中转网关）同理：在各自控制台创建 key，
接口地址填它们的 base 地址（例如 `https://api.moonshot.cn`），模型名填它们提供的名字。

> **不要**去 `%USERPROFILE%\.dsh\.credentials.yaml` 里找 key。那个文件里是 DSH 客户端自己
> 登录 `platform.deepseek.com` 的会话凭据（字段名 `token` / `secret`），不是 API key，
> 粘进插件也不能用，而且属于不该外传的登录态。

**接口地址怎么填**：只填 `https://api.deepseek.com` 即可，插件会自动补成
`https://api.deepseek.com/chat/completions`（官方文档给的端点；不会擅自加 `/v1`）。
若你用的网关要求 `/v1/chat/completions`，就直接把完整地址填进去。

**只有两件事是插件固定的、改不了**：
1. **输出格式契约**（`{"score":0-100,"reason":"...","risks":["..."]}`）—— 解析器靠它读分数，
   会自动追加在你的自定义判断标准后面；
2. **画像原样透传** —— 你写什么就发什么，插件不加任何解读或注解。

改了自定义判断标准后，打分缓存会自动失效（缓存键包含提示词），不会拿到旧结论。

**成本**：每条职位 1 次请求，结果按「岗位 + 画像」缓存，同一岗位不会重复计费。
点「清空打分缓存」可强制重新打分。

**注意**：改了画像或阈值后，若想重新评估**之前被 AI 拒掉**的岗位，必须先点「清空已处理记录」，
否则那些岗位已经被标记为处理过、不会再被看一眼。

## 5. 新岗位刷新怎么配

「新岗位刷新」面板勾上「启用」，填间隔分钟数（默认 10）。

行为：一轮岗位翻到底 → 等待 N 分钟 → 重新搜索关键词 → 只投历史记录里没有的新岗位 →
直到达到「单次最多投递数」或你点「停止」。

前提：**那个 BOSS 标签页要一直开着**；电脑睡眠会暂停 JS 计时，任务会卡住。

## 6. 页面自检（页面改版时用它，别盲猜）

弹窗底部点「自检」，会输出：

- 当前页面地址、是否在职位搜索页
- 职位卡片数量
- 每个选择器的命中数（`jobCard` / `jobTitle` / `nextPageButton` / `searchInput` …）
- 首张卡片的标题 / 公司 / 薪资 / 是否有详情链接
- 下一页按钮的文字
- **能否抓到 JD**（成功会显示字数）

最后会给一句人话结论，例如「结论：卡片能读到，但抓不到职位详情 —— AI 只能按标题/标签打分」。

**如果自检结果异常，请把这段文本整段发我**，我据此校准 `selectors.js`，不用来回猜。

## 7. 设置项与运行中的行为（含 v1 原有）

| 设置 | 行为 |
|---|---|
| 岗位关键词 | **第一个**自动填入搜索框发起搜索；**全部**用于筛选（标题/标签/JD 命中任一即匹配）；留空=不限制 |
| 排除关键词 | 匹配「标题 + 标签 + 公司名 + JD」，命中即跳过。建议填 `外包, 驻场, 众包` |
| 期望薪资 | ①在 BOSS「薪资待遇」选重叠最多的档位；②再本地二次过滤 |
| 求职类型/经验/学历 | 开始任务时自动点到原生筛选下拉；「不限」=不动 |
| 打招呼话术 | 逐字输入后发送；留空用内置默认话术。**⚠️ 见下方第 6 条的实测说明：BOSS 现在多数岗位不给输入框，直接用你账号里的默认招呼语** |
| 单次最多投递数 / 间隔 | 默认 20 个 / 3~8 秒随机。**建议先 5~10 个试水** |

运行中：实时日志（`已投递 / 已跳过 / 异常`）、工具栏图标显示已投递数角标；
**关闭弹窗不中断任务**，页面里继续跑；点「停止」才停。

**失败不拉黑**：AI 打分失败、找不到按钮、页面加载慢等**技术性失败不会标记为已处理**，下次运行自动重试。

## 8. 常见问题

**① 提示「未找到聊天输入框」**：该职位多半要先完善简历，属技术性失败，下次会重试。

**② 日志说"使用了 BOSS 自带的默认招呼语"** —— **这是实测中最重要的一条**：
2026-11-16 真实投递 4 个岗位，**4 个全部**用掉了 BOSS 账号里的默认招呼语，插件里填的自定义话术一次都没生效。
原因是现在 BOSS 点「立即沟通」后直接把默认招呼语发出去、并弹「已向BOSS发送消息」确认框，页面上根本没有输入框。
**所以你想让话术生效，必须去 BOSS 里改**：网页版 →「消息通知」→「设置招呼语」→ 改掉默认文案。

**③ 一直找不到职位卡片 / 打招呼按钮**：先点「自检」把结果发我。
如果确实改版了，也可自行修 `src\shared\selectors.js`（把新选择器**追加**进对应数组，保留旧的），
然后 `edge://extensions` 点「重新加载」+ 刷新 BOSS 页面。

**④ 想重投同一批岗位**：点「清空已处理记录」（会弹确认框）。

**⑤ 点「开始投递」没反应**：确认地址是不是 `www.zhipin.com/web/geek/job...`、装/更新后有没有刷新页面、
`edge://extensions` 里是否「已启用」。

**⑥ AI 打分一直失败**：看日志里的错误码 —— 401/403 是 Key 无效，429 是限流，
「等待后台响应超时」多半是网络或接口地址不对（先在地址栏能打开那个域名）。

**⑦ 薪资显示成 `-K·薪`、没有数字**：这是 BOSS 用自定义字体做的反爬混淆，列表页抓不到数字。
插件会自动改从**职位详情页**取薪资区间来兜底；如果详情页也拿不到，薪资过滤会被**静默跳过**
（不会误杀岗位），此时建议靠「求职画像 + AI 打分」来把关。

**⑧ 卡片上找不到"打招呼"按钮**：属正常。BOSS 的按钮是**鼠标悬停后才渲染**的，
插件会先派发 hover 事件再查找；实在找不到才退化为"点开卡片"，且点完若列表消失会放弃该岗位、
避免整页跳转把任务弄丢。

**⑨ 日志里看不到"翻页"，只看到"滚动到底部，加载了更多职位"**：这是正常的 ——
BOSS 的职位列表是滚动加载，不是分页。插件会自动滚动到底触发加载，
日志里每出现一次这句，说明又多加载了一屏岗位。

## 9. ⚠️ 风险提示

1. **自动打招呼 / 批量投递可能违反 BOSS 直聘用户协议**，可能限流或封号，风险自负。
2. 保持保守参数：间隔 3~8 秒以上、单次 5~20 个、别长时间挂机。
3. 话术认真写，别群发。
4. 运行期间不要关闭那个 BOSS 标签页；电脑别睡眠。
5. MIT 开源，作者与改造者不对使用后果负责。

## 10. 目录结构

```
BossAutoApply\
├── manifest.json            # MV3：storage/scripting/activeTab；host 仅 zhipin + api.deepseek.com
├── package.json             # "test": "node --test"
├── src\
│   ├── background\background.js   # 进度缓存 + 大模型代理 + 分数缓存 + 存活心跳
│   ├── content\content.js         # 主流程：搜索/筛选/JD抓取/打分/打招呼/翻页/续跑/自检
│   ├── popup\popup.html/.css/.js   # 设置面板（含 AI 与刷新配置、自检）
│   └── shared\
│       ├── utils.js        # 列表签名、hash、截断、退避（纯函数）
│       ├── selectors.js    # 全部页面选择器（改版只改这里）
│       ├── matcher.js      # 纯函数：规则匹配（含 JD）
│       └── scoring.js      # 纯函数：提示词构建、响应解析、缓存键、阈值判断
└── test\                    # 27 个单元测试
```

存储键：配置 `ba_config`、已处理岗位 `ba_seen_job_ids`、打分缓存 `ba_score_cache`、
续跑状态 `ba_run_state`、进度 `ba_latest_state`（session）。
